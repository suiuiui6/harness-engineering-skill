## 决策：从 Layer 2 重入

**直接回答：**

- **应重入：Layer 2（拓扑与桥接验证）**
- **不是 Layer 1：** 两个组件各自的单组件实测记录已完整（component-level proof 已具备），回退到 Layer 1 属于过度回滚（over-rollback）。Layer 1 是组件级 MVP 验证层，而这里的问题不在单个组件的能力证明上——每个组件单独运行都已有实测 trace。
- **不能直接集成：** 桥接段只有文档描述 + 口头保证，缺的是 **stage-by-stage 运行 trace** 和 **可回放的 payload 记录**。运行时事实（runtime facts）压倒文档和非正式承诺——没有桥接实测证据就集成，是在未经验证的桥接假设上构建功能。

**具体操作：**

重入 Layer 2 后，需要：
1. 重新打开拓扑定义，对齐两端的 schema 边界；
2. 补充 stage-by-stage 桥接验证，产出行走的 trace；
3. 录制可回放 payload，写入 docs 作为桥接事实记录；
4. 如果桥接假设在上游验证中失败，则最小化回滚到 Layer 1 仅修复失败点，而不是整体推倒。

**一句话原则：** 组件证明完整 ≠ 桥接证明完整。不在未经实测的桥接上集成。
