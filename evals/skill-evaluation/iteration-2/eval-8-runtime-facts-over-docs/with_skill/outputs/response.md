## 处理方式：拒绝直接集成，退回证据收集

**决策：不能相信文档直接集成。必须先退回 Layer 1 收集单组件实测记录，再进 Layer 2 验证桥接阶段运行证据。**

---

### 具体行动

1. **冻结集成建议。** 缺少单组件实测记录（Layer 1）和桥接运行证据（Layer 2），直接集成的提议不满足 Harness Engineering 的证据准入条件，立即搁置。

2. **退回 Layer 1 — 单组件证据收集。** 对桥接流程涉及的每个组件逐一做运行时测量：实际调用是否返回预期结果、超时/错误边界是否成立、输入输出合约是否与桥接文档描述一致。每个组件产出实测记录，而非引用文档声明。

3. **进入 Layer 2 — 桥接阶段验证。** 在 Layer 1 证实的组件基础上，对桥接链路做端到端逐段运行：上游输出 → 中间转换 → 下游接收，验证全链路可复现。产出桥接阶段的运行日志或 trace，作为通行证据。

4. **写回事实或最小回滚。** 如果实测与文档一致，将运行证据写回文档，替换掉无实测支撑的声明，然后重新评估集成。如果实测暴露了文档中不存在的断裂，最小化回滚：只修断裂点，不扩大改动面。

---

### 依据的方法规则

| 规则 | 本场景的适用 |
|---|---|
| **Runtime facts outrank stale documents** | 文档声称桥接已打通，但无运行时证据，文档不可作为权威来源 |
| **If single-component proof is missing, return to Layer 1** | 没有单组件实测记录，必须退回 Layer 1 逐组件收集 |
| **If bridge evidence is missing, return to Layer 2** | 没有桥接阶段的运行证据，必须退回 Layer 2 逐段验证 |
| **Do not integrate on unproven assumptions** | "先相信文档"即是在未证实假设上集成，直接违反此规则 |

**一句话总结：文档是声明，不是证据。集成要通行证，Layer 1 和 Layer 2 两张通行证都缺，不能放行。**
